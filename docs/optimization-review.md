## 改动与验证

| 范围 | 结果 | 验证依据 |
|------|------|----------|
| ICMP 响应匹配 | 错误报文中的原始目标地址必须匹配当前请求，防止相同请求编号的其他目标响应干扰检测 | 本地报文回归测试覆盖超时、目标不可达和 IPv4 选项头 |

| 超时与取消 | 从发送时刻计算截止时间；已取消请求不返回成功；按时到达的排队响应仍有效；发送前的旧响应被忽略 | 发送截止时间、排队响应、取消竞争与旧响应测试 |
| 阻塞发送 | 写入受请求超时及取消约束；取消回调结束后才释放共享发送锁 | 阻塞管道测试覆盖写入截止时间、较早的上下文截止时间、取消及后续发送 |
| 代理响应 | 校验 JSON 后返回原始内容，避免缩进扩容与额外大缓冲区 | 嵌套报文测试：4,097 字节输入不再膨胀为 4,202,498 字节；数字与转义内容保真测试 |

| 密码验证 | 导入、导出使用统一 API 地址及超时设置；保留错误密码、限流及网络失败处理 | 实际 HTTP 测试覆盖自定义路径、表单编码、超时、取消和响应状态；页面测试覆盖失败后的控件恢复 |

## 2026-09-16 连接池恢复补充

- 修复 ICMP 底层连接意外关闭后仍保留失效连接的问题：读取循环收到 `net.ErrClosed` 后清理对应连接并释放等待请求，后续请求可重新初始化连接。
- 清理时核对连接身份，防止旧读取循环延迟退出时关闭新连接；沿用初始化锁、发送锁的既有加锁顺序。
- 新增 UDP 本地套接字回归测试，覆盖意外关闭、等待请求释放、连接重建和旧读取循环隔离，无需原始套接字权限。修改前测试因等待请求未释放而失败，修改后通过。
- 已通过 `go test ./src/...`、`go vet ./src/...`、`scripts/test-race-windows.ps1` 全量竞争检测、前端 85 项测试及 `npm run lint`。

## 2026-09-16 稳定性与资源占用补充

- 丢包率改为按发送数、接收数使用整数计算，统一用于定时 Ping、地图探测和在线工具，保留原有向下取整规则。旧浮点算法将 29/100、57/100、29/50 分别少算为 28%、56%、57%。回归测试复现了 29% 阈值报警漏报，并验证修复后数据写入与报警判定。
- 文件日志增加 10 MiB 轮转及最多 3 个备份，限制持续追加造成的磁盘增长。按级别共 3 类日志，普通日志总容量最多约 120 MiB；已有超大文件及单条超大日志完整保留，容量可暂时超过该值。标准输出的留存仍由运行环境负责。
- 轮转测试使用实际文件，覆盖旧备份淘汰、重启后的大小统计、超大日志、文件系统操作失败后重试，以及并发写入时日志完整性。原有日志分级、重初始化及关闭释放文件的测试继续通过。
- 本轮修改后通过 `go test ./src/...`、`go vet ./src/...` 及 `scripts/test-race-windows.ps1` 全量竞争检测。前端源码未修改，前端测试结果沿用上一轮验证。
