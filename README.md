## 功能

- 正向PING，反向Ping绘图
- 互PING间机器的状态拓扑，自定义延迟、丢包阈值报警（声音报警），报警时MTR检测
- 全国PING延迟地图（各省份可分电信、联通、移动三条线路）
- 检测工具，支持使用SmartPingNext各节点进行网络相关检测
- 节点编辑（支持修改节点名称和IP地址，自动同步关联配置）
- 配置导入/导出
- 支持深色/浅色主题切换
- 设置面板统一管理主题与语言
- 中英双语界面，支持运行时切换（无需刷新）
- 可收缩侧边栏
- 单文件部署，无需额外配置文件

## 技术栈

- **后端**: Go 1.24 + SQLite3（纯 Go 实现，无 CGO 依赖）
- **前端**: Vue 3 + TypeScript + Vite + Element Plus + ECharts

## 快速开始

### 下载发布版

从 [Releases](https://github.com/Antman2023/SmartPingNext/releases) 下载对应平台的版本：

| 平台 | 架构 | 文件 |
|------|------|------|
| Linux | amd64 | smartping-linux-amd64.tar.gz |
| Linux | arm64 | smartping-linux-arm64.tar.gz |
| Linux | armv7 | smartping-linux-armv7.tar.gz |
| Windows | amd64 | smartping-windows-amd64.zip |
| macOS | arm64 | smartping-darwin-arm64.tar.gz |

```bash
# Linux/macOS
tar -xzf smartping-*.tar.gz
./smartping

# Windows
# 解压 smartping-*.zip
# 双击运行 smartping.exe
```

首次运行会自动创建 `conf/`、`db/`、`logs/` 目录并释放默认配置文件。

文件日志按级别写入 `info.log`、`debug.log` 和 `error.log`。每个文件达到 10 MiB 后在下次写入前轮转，最多保留 3 个备份（`.1` 最新、`.3` 最旧），更早的日志自动删除；重启后继续按现有文件大小轮转。单条超大日志会完整保留，因此单个文件可能超过 10 MiB。默认日志级别为 `info`，可通过 `SMARTPING_LOG_LEVEL` 调整。标准输出仍保留，由 Docker 等运行环境管理其日志留存。

### 从源码构建

需要 Go 1.24+，以及 Node.js 20.19+ 或 22.12+。

```bash
# 前端
cd web
npm ci
npm run build:embed

# 后端
cd ..
go build -o smartping src/smartping.go
```

`build:embed` 支持 Windows、Linux 和 macOS，会在前端构建成功后替换 `src/static/html` 中的生成文件，避免重复复制产生嵌套目录或打包旧资源。仅开发前端时仍可使用 `npm run build`。

### 本地开发与验证

完成上述前端构建后，启动上一步构建的程序（Linux/macOS 使用 `./smartping`；Windows 可先执行 `go build -o smartping.exe ./src`，再运行 `.\smartping.exe`），再打开另一个终端进入 `web` 并运行 `npm run dev`。浏览器访问终端显示的开发地址（默认端口 3000），API 请求会代理到 `http://localhost:8899`。

运行时配置、数据库和日志存放在可执行文件旁的目录中。为保留开发数据，使用固定位置的构建产物，而非 `go run` 的临时程序。

可在 `web/.env.development.local` 中覆盖以下设置，修改后重启开发服务：

| 变量 | 默认值 | 用途 |
|------|--------|------|
| `VITE_PROXY_TARGET` | `http://localhost:8899` | 开发代理的后端地址 |
| `VITE_API_BASE_URL` | `/api` | 浏览器请求的 API 前缀，包含配置和密码验证接口 |
| `VITE_API_TIMEOUT` | `15000` | 普通 API 请求超时，单位为毫秒；节点代理请求会留出额外响应时间 |
| `VITE_DEFAULT_TIME_RANGE` | `6` | 正向与反向详情的默认小时数，允许 1 分钟至 31 天；无效值回退到 6 小时 |

使用开发代理时保留 `/api` 前缀，只修改 `VITE_PROXY_TARGET`。代理保留浏览器的 `Host` 和 `Origin`，以兼容后端对配置操作的来源检查。`VITE_` 变量会进入前端代码，不能用于保存密码；生产环境修改这些变量后需要重新构建前端及 Go 程序。

```bash
# web 目录：测试与静态检查（包括本地代理集成测试）
npm test
npm run lint

# 项目根目录：后端测试与静态检查
go test ./src/...
go vet ./src/...
```

配置导入仅接受不超过 16 MiB 的文件，导入后仍需保存才会应用到节点。导入、导出密码验证失败或超时不会丢弃当前编辑内容。

导入缺失的拓扑显示或报警规则字段时，会给出对应的校验提示并保留当前草稿。基础参数中的扩展项同样必须是安全整数，小数和超出精确整数范围的数值会在导入或保存前被拒绝；修正后可重试。

配置加载成功前及重载期间暂停保存、导入和导出；进行中的保存、导入或导出也会阻止配置重载覆盖当前草稿。页面卸载后，延迟回调不会发起新的配置请求、密码验证或保存。保存等待期间新增的编辑仍保留，成功提示只确认已提交的快照。

保存校验失败时，只在当前配置页内定位仍存在的错误。离开页面、重载配置、修正错误或开始新的操作后，旧定位不会移动焦点；连续校验时只处理最新一次定位，并遵循系统减少动画的偏好。

离开配置页的确认返回后会再次检查保存、导入和导出状态，防止较早打开的确认框中断后来开始的操作。刷新或关闭页面时，未保存修改及进行中的操作都会请求浏览器显示离开提示。

配置草稿比较按精确键名排序，不依赖语言排序规则；同一配置的对象键顺序变化不会产生未保存提示，数组顺序变化仍视为修改。地图项名为 `__proto__` 时，编辑也会正确更新未保存状态并包含在提交中。

地图项名为 `__v_isReactive`、`__v_raw` 等响应式内部标记时，同样作为普通数据键保留。加载、编辑、导入、导出、保存及删除保持原名称和运营商地址，新增或删除会更新计数和未保存状态；编辑其它地图项不会使尚待确认的独立目标失效。

模式、基础参数、拓扑设置和拓扑规则中的扩展字段也保留原键名及标量类型，包括空字符串和零值。编辑拓扑规则保留已有规则的扩展字段和相对顺序，新选目标追加到末尾。

删除节点或省份的确认只作用于发起时的目标；等待期间重载、导入或替换配置后，旧确认不会删除新的对象。切换省份编辑时，确认只删除原先选中的省份，并保留后来打开的编辑窗口；取消或重复完成确认不会误报成功。删除节点会移除指向它的 Ping 和拓扑规则。

节点、Ping、拓扑与省份编辑弹窗分别保留自己的目标。关闭弹窗或替换目标后，旧保存回调不会修改草稿或报成功；配置重载、导入成功会关闭旧弹窗，失败时保留原编辑内容。Ping 与拓扑设置不会重新写入已移除、换址或替换的目标，重新打开弹窗后可使用最新节点列表编辑。

新增节点和省份也绑定打开弹窗时的配置集合，关闭、卸载或替换配置后的旧确认不会添加记录。字段校验失败会保留输入与弹窗，节点达到 1024 个时阻止继续添加，删除节点后可用原输入重试。新增记录仍需保存整份配置才会应用。

正向与反向监控刷新失败时，会保留同一查询最后成功加载的曲线并显示失败状态。详情页切换目标、相对时间范围或有效的自定义时间范围时，会清除旧查询的曲线，避免混用数据。

监控详情弹窗关闭后不会接受延迟触发的查询；页面卸载会取消进行中的请求和刷新定时器，并阻止延迟回调重新加载配置、列表或详情。重新打开弹窗后可正常查询。

历史 Ping 查询直接复用有序的分钟时间轴定位采样，减少长时间范围查询的索引内存开销。缺失采样仍显示为 `-`，实际零延迟和 100% 丢包保持原值；时钟回拨等无序时间轴沿用原有索引方式。

Ping 时间轴的分钟标签按取消检查批次共享请求内的字符串缓冲，减少长查询中逐分钟创建字符串的分配次数。每批最多 256 分钟，已生成标签保持不变；取消检查、节点时区与回拨规则继续沿用原流程。

读取到首条 Ping 采样后，时间索引准备也会检查请求取消与截止时间；顺序判断和回拨位置映射每处理 256 个标签再次检查。取消会丢弃未完成索引并关闭数据库游标，正常请求仍将重复标签定位到最后一次出现的位置。

报警历史按响应节点保留同一日期查询的最后成功记录。节点刷新失败时，对应记录继续显示并标明“刷新失败”；成功响应会替换这些记录，包括成功返回空列表。切换日期或重载节点配置会清除旧记录，全部节点刷新失败时保留上次成功更新时间。

报警历史在发布响应前校验归档日期与记录时间。不存在的日历日期、越界时间或无效后缀会按节点刷新失败处理，保留此前成功数据。校验不依赖浏览器时区、不改写节点时间标签，继续兼容已有秒、小数秒、时区后缀和 SQLite 的 24 小时写法；MTR 错误文本仍可作为记录保存。

报警记录按保存的年月日、时分秒和小数秒倒序排列，混用空格或 `T` 分隔符不会影响顺序，原始标签和来源失败标记保留。相同时间保持原顺序，24 小时写法按次日时间比较。节点未提供时区元数据，因此仍比较各节点保存的本地时间字段，不将跨节点记录转换为统一绝对时刻。

报警历史在配置重载期间暂停日期切换和刷新，重载成功后继续查询当前选中日期并使用新节点地址与端口。退出页面会取消在途请求并停止排队任务；延迟回调不会发起新查询或改变选中日期，首次配置加载失败后仍可重试。

地图的日期查询与刷新回调也会等待配置加载完成，避免重载期间使用旧地址重复请求、清除已有地图或取消配置加载发起的首个查询。重载后继续查询选定时间，后续节点切换使用新端口；首次配置加载失败后可通过刷新重试。

报警日期列表通过现有日期索引逐日查找，减少大量同日记录时的读取开销，保持日期倒序与异常记录的错误处理。稀疏记录的查询有少量额外开销，具体基准见 [优化验证记录](docs/optimization-review.md)。

在线检测、定时 Ping、地图探测及告警 MTR 的域名解析最多等待 5 秒；调用方取消或更短的截止时间会提前结束解析。直接填写 IPv4 地址会跳过 DNS。

在线检测在配置重载期间暂停新任务，完成后使用新的探测节点地址和端口；页面卸载会取消在途请求，并阻止延迟回调重新发起检测。HTTP 成功响应中节点明确返回的限流、解析失败等原因会显示在对应行；缺少有效失败原因或成功数据格式异常时提示格式错误。HTTP 错误与请求取消继续沿用统一分类。

在线检测的成功统计还需满足计数与丢包百分比一致、已有回复时最小延迟不大于平均延迟且平均延迟不大于最大延迟；仅收到一次回复时三项延迟必须相同。未发送探测的成功响应会被拒绝，合法零延迟与全部丢包占位值继续显示；异常节点不影响其它节点完成。

全国延迟地图在同一查询刷新失败时保留上次结果和更新时间，并持续提示当前显示旧数据；成功刷新后清除提示，切换节点或时间会清除旧查询结果。配置重载期间暂停节点切换，已移除节点及页面卸载后的延迟回调不会发起新查询。

拓扑页在配置重载期间暂停手动刷新，重载成功后使用新的节点列表、地址和端口。页面卸载会取消配置与节点请求、停止派发排队任务，并阻止延迟回调发起新的配置或拓扑查询。

拓扑刷新逐节点更新状态和加载标记，减少大量节点时重复复制整张状态表的开销。节点完成后仍立即更新颜色、链路和加载计数；失败节点显示加载失败，重新刷新可恢复，已不再监控的来源状态会被清理。

等待 ICMP 连接初始化锁或共享发送锁时，调用方取消或达到截止时间也会中断排队；排队发送不会阻挡其他探测响应的分发。单次探测的响应超时仍从发送时刻计算。

ICMP 连接读取失败时，以 10、20、40、80 毫秒的间隔重试；连续第 5 次失败后关闭连接，释放尚未收到响应的等待请求，后续探测再按需重建。任何成功读取都会重置连续失败计数；旧连接的读取线程不会清理已替换的新连接。

Ping、报警、地图结果存储与归档清理在等待共享数据库写入锁时，也支持上下文取消和截止时间。取消排队不会写入或删除记录，后续正常任务仍可继续使用写入锁；服务关闭时，排队任务可以及时退出。

地图采样轮次、结果发布和存储在等待地图结果锁时也支持取消与截止时间；在取得结果锁之前退出的轮次保留已有结果。存储快照每复制 256 个样本检查取消，并在各运营商排序前和全部排序后、JSON 编码前后检查；取消时丢弃部分快照，不写入数据库。单个运营商的标准排序和标准 JSON 编码仍需完成后才能观察取消。

服务关闭使用 15 秒宽限期，停止接收新连接并允许已有 HTTP 请求完成。宽限期结束后关闭剩余 HTTP 连接，取消对应请求及其排队查询；关闭未完成时仍返回错误并保留数据库，避免提前关闭尚在使用的资源。

定时 Ping 按每次探测的实际开始时间加 `PingIntervalMs` 安排下一次探测。单次探测阻塞或任务调度延迟后，不会集中补发落后的探测；仍执行配置的探测次数，因此整轮耗时可能延长。

MTR 将首次路径发现探测计入每个跳点的采样节奏，第二次探测也遵守一秒间隔；后续按各次探测的实际开始时间调度，慢探测后不会集中补发。各跳点继续并行采样，等待间隔时支持取消和截止时间。正常完成采样的跳点共探测 10 次；达到连续超时停止条件的最后一个跳点仅保留首次超时记录。

Windows 上可使用 Zig 运行 Go 数据竞争检测：安装 Go 和 Zig 并加入 PATH 后，在项目根目录执行 `pwsh -File scripts/test-race-windows.ps1`。脚本使用 `zig cc`，为 race 测试补充 Windows 同步库和固定加载方式，并在退出时恢复环境变量；正式构建仍不依赖 CGO。此流程已在 Go 1.27.1、Zig 0.16.0、Windows amd64 上验证。

资源同步会先完整复制到临时目录，再替换旧版。复制失败会保留旧版，替换失败会尝试恢复旧版；如果恢复也失败，命令会报告保留的备份路径，便于手动恢复。

部署到子路径（例如 `/smartping/`）时，先在 `web/.env.local` 设置 `VITE_API_BASE_URL=/smartping/api`，然后在 `web/` 下运行：

```bash
npm run build -- --base=/smartping/
node scripts/sync-embed.mjs
```

随后重新构建后端。反向代理需要将 `/smartping/` 下的请求转发给 SmartPing，并去掉该前缀（例如 `/smartping/api/config.json` 转发为 `/api/config.json`）。前端路由与静态资源会使用构建时指定的基路径。

### Docker

支持多架构镜像：`linux/amd64`、`linux/arm64`、`linux/arm/v7`

```bash
docker pull pathletboy/smartping-next:latest

# 运行容器
docker run -d \
  --name smartping \
  -p 8899:8899 \
  -v smartping-conf:/app/conf \
  -v smartping-db:/app/db \
  -v smartping-logs:/app/logs \
  --restart unless-stopped \
  pathletboy/smartping-next:latest

# 或自行构建
docker build -t smartping-next:latest .
docker run -d --name smartping -p 8899:8899 smartping-next:latest

# 或使用 docker-compose
docker-compose up -d
```

**默认端口**: 8899 | **默认密码**: smartping

## 设计思路

本系统的定位为轻量级工具，即使组多点成互Ping网络可以遵守无中心化原则，所有的数据均存储自身节点中，每个节点提供出方向的数据，从任意节点查询数据均会通过Ajax请求关联节点的API接口获取并组装全部数据。

## 目录结构

```
├── src/                    # Go 后端源码
│   ├── smartping.go        # 程序入口
│   ├── g/                  # 全局配置和数据结构
│   ├── http/               # HTTP 服务层
│   ├── funcs/              # 核心业务逻辑
│   ├── nettools/           # 底层网络工具
│   └── static/             # 嵌入的静态文件
│       ├── html/           # 前端页面
│       ├── conf/           # 默认配置
│       └── db/             # 默认数据库
├── web/                    # Vue 3 前端源码
│   ├── src/
│   │   ├── views/          # 页面组件
```

## API 端点

| 端点 | 方法 | 描述 |
|------|------|------|
| `/api/config.json` | GET | 获取配置 |
| `/api/ping.json` | GET | 获取 PING 数据 |
| `/api/topology.json` | GET | 获取拓扑状态 |
| `/api/alert.json` | GET | 获取报警日志 |
| `/api/mapping.json` | GET | 获取地图数据 |
| `/api/tools.json` | GET | 在线检测工具 |
| `/api/saveconfig.json` | POST | 保存配置 |
| `/api/proxy.json` | GET | 代理访问远程节点 |

`/api/ping.json` 返回的指标数组与 `lastcheck` 时间轴逐项对应，数值使用字符串表示。没有采样记录的分钟使用 `"-"`，图表显示为断点；`"0"` 是真实记录的零值，不能与缺失采样混同。API 客户端应在转换数字前处理 `"-"`。查询时间和返回的时间轴均使用节点时区。

前端在更新 Ping 曲线前检查时间轴的完整分钟标签、公历日期与时分范围，以及指标字符串的完整十进制格式。异常响应按刷新失败处理，保留此前成功曲线；全部来源失败时不推进成功更新时间。校验不使用浏览器时区，不排序或去重时钟回拨产生的时间标签；合法空响应仍会清除旧曲线。

Ping 详情图和小图也能正确显示带负号年份标签的月日与时分。原始时间轴、测量值和悬浮提示保留节点输出，不按浏览器时区转换。

地图响应的 `subtext` 同样按节点输出的完整分钟格式、公历日期与时分范围校验。异常响应按刷新失败处理，同一查询保留上次地图和成功更新时间；切换节点或时间仍清除旧查询结果。合法空地图正常清除旧数据，标签不按浏览器时区转换。

Ping 和地图查询的显式分钟参数如果因节点时区跳变而不存在，接口返回 `406`，不会自动改成另一个时刻。原有短小时和额外空格写法继续兼容。报警日期查询按指定日的 `00:00` 至次日 `00:00` 筛选数据库时间标签，避免午夜时区跳变导致日期范围偏移。

Ping 历史查询使用实际时间轴中所有分钟标签的范围读取记录，避免时钟回拨时遗漏首尾标签之外的中间采样。数据库仍按本地分钟标签存储；重复标签对应时间轴上最后一次出现的位置，无法区分回拨前后同名分钟的独立记录。

历史 Ping 查询在准备时间轴时响应客户端取消和截止时间。已经取消的请求跳过时间轴分配；准备过程中取消会停止构建，随后不查询数据库，也不返回部分历史数组。参数校验和未取消请求的响应格式保持原规则。

Ping 与报警历史在同一次请求中复用数据库行扫描对象，减少大量记录读取时的临时分配；空结果不创建扫描对象。读出的字符串与报警记录仍按值保存，原始测量、归档日期、来源信息及错误处理保持不变，具体分配基准见 [优化验证记录](docs/optimization-review.md)。

Ping 记录、报警日期与报警记录的读取在首行处理前及之后每 256 行检查请求取消和截止时间。结束的请求停止继续处理缓冲行、关闭游标并释放查询资源，不返回部分成功结果；后续查询仍可使用数据库连接池。

归档截止日期按节点当前本地日历日期减去 `Base.Archive` 天计算，再删除截止日期之前的 Ping、报警和地图记录；截止日期当天及更新记录会保留。午夜跳时或整日被跳过时，截止日期不会随本地时刻归一化而偏移。

报警历史响应中的日期列表和所选日记录来自同一个数据库快照，避免混用并发采样写入或归档删除前后的数据。快照在编码和发送 JSON 前结束；后续请求读取最新提交的记录。

配置、Ping、拓扑、报警与地图的只读 JSON 接口在编码前和提交响应前检查请求取消与截止时间。已取消的请求跳过编码；编码期间取消会丢弃编码结果。标准 JSON 编码本身不能中途打断。代理在远端响应读取完成后也检查取消，避免继续转发完整响应，并释放响应体与并发名额。

配置接口在复制快照前和复制过程中也检查取消；已结束的请求跳过整份配置复制，中途取消会丢弃部分结果并释放读锁。现有配置锁的等待不能中断，获取锁后会再次检查请求状态。正常响应继续隐藏密码，并保留完整配置及空集合的原有表示。

地图历史还在解析数据库中的 JSON 前检查取消和截止时间，避免为已经结束的请求继续解析并复制地图数据。解析过程中取消会在解析结束后退出，复制过程中取消会丢弃部分结果；标准 JSON 解析本身不能中途打断。

地图输出按运营商的已解析样本数量一次性分配结果数组，减少大量数据的重复扩容；空运营商仍返回空数组。分配在首个样本通过取消检查和数据校验后进行。

`/api/topology.json` 按目标 IP 返回字符串状态：`"true"` 表示未达到告警阈值，`"false"` 表示达到告警阈值，`"unknown"` 表示配置的检查窗口内没有该目标的采样（包含跨分钟完成采样的宽限时间）。未知状态不触发告警，也不将已有告警标记为恢复。客户端应显式处理三种值，不能将非 `"false"` 值一律视为正常。

告警检查窗口至少为 10 小时时，查询可在最新采样中的异常次数达到阈值后提前结束；仍按配置限制采样数量，保留跨分钟宽限及无样本状态。较短窗口继续使用原查询，避免增加常用短窗口的固定开销。长窗口内仅有少量采样或无采样时，新查询会有额外开销；测量结果见 [优化复盘](docs/optimization-review.md)。

节点代理响应最多读取 16 MiB，最多同时执行 32 个请求。声明长度在 512 字节至 16 MiB 范围内时，代理预分配读取缓冲区以减少大响应扩容；实际读取量仍独立检查，截断或超限响应不会作为有效数据返回。客户端取消会中断远端请求并释放代理并发名额。

代理在分配读取缓冲区前检查取消，并对可取消请求按最多 32 KiB 的读取批次检查状态，避免取消后继续消费已缓冲的大响应。取消检查与字节上限共用读取器，减少独立包装对象的分配。读取或最终校验期间取消会丢弃结果，响应体和并发名额仍释放；已按声明长度完成的分配不会因后续取消而免除。阻塞中的网络读取由 HTTP 传输层中断。

节点 JSON API 和代理输出按编码后的字节数声明 `Content-Length`，使大响应能够使用上述预分配读取。密码与在线工具的限流 JSON 同样声明准确长度，并保留 `429` 状态、`Retry-After` 和原有字段。
